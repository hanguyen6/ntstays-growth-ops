NTStays Growth Ops

Designed and deployed a production-grade AI-powered marketing and revenue-operations platform that automates lead management, campaign attribution, reporting, and customer communications while maintaining human approval controls.

Technical stack Claude API · n8n · HubSpot · Stripe · Cloudflare Access · GitHub Actions · Python
What's the most boring marketing workflow you could automate end-to-end this week?
The monthly channel report.

Pull each platform's numbers, reconcile them, chart them, write the summary, send it. At NTStays it now runs end to end: on the 1st of each month an n8n workflow computes the numbers in code, Claude writes the summary, a check blocks any draft with a number that isn't in the data, and the owner approves before it goes out. Its first scheduled run, on October 1, 2026, showed why the check matters: it caught a number the AI had calculated on its own and held the draft back.

Business Problem

NTStays receives inquiries and bookings from multiple channels, each with different data semantics. Customer inquiries were handled manually, source attribution was inconsistent, and platform reporting mixed monthly, rolling-window and lifetime metrics. The operating question was simple but hard to answer reliably: which channel is actually producing valuable business, at what cost?

Governance & Reliability

Controls

  • Human-in-the-loop approval before customer communications
  • Structured outputs for predictable downstream processing
  • Input validation and required-field checks before routing
  • Role-based access controls for sensitive actions
  • Workflow logging and approval audit trails

Operational resilience

  • Workflow monitoring, run history, and incident alerts
  • Error handling and recovery paths for failed automations
  • Data-quality checks for attribution and reporting inputs
  • Version-controlled workflow changes and deployments
  • Escalation paths for ambiguous requests

Failures & Fixes

A production system becomes credible when the failure modes are visible. These were some of the most useful engineering lessons.

FailureRoot causeChange made
Test data appeared on the production dashboardThe stats test suite wrote sample output into the production data file.Production builds now use only real exports; a regression test verifies tests never touch the production path.
Chat refused real visitorsThe Cloudflare Turnstile challenge was off-screen, so users could not complete it.The widget was made visible, with a 30-second wait and explicit Cloudflare error codes.
The website deployed before its backendSite deployment was automatic but n8n import was still manual.Added tested, key-restricted automated n8n deployment.
Updating one Airbnb rate erased anotherThe initial “latest row replaces the month” logic was too broad.Metrics now merge field-by-field; blank values never erase known data.
Backfilled leases distorted conversionLeases were dated by entry date rather than signed date.Added signed-on date, defaulting appropriately to move-in.
Furnished Finder funnel math was misleadingInquiry totals were cumulative while views were rolling 90 days.Monthly inquiries are derived from entry differences, per listing; incompatible periods are not divided.
Prompt caching was assumed but not activeThe prompt was below the model's caching threshold.Documented the behavior and accepted the negligible cost at this volume.

Key Learnings

The project reinforced several principles I would carry into larger enterprise AI systems.

1. Put rules in code

A prompt can request safe behavior. A deterministic check can enforce it.

2. Data semantics matter more than charts

Rolling windows, running totals, averages and business dates caused more risk than the visualization layer.

3. Tests must be isolated from production

The most damaging bug came from the test environment writing to a production data path.

4. Label what every number means

Thin or mixed-period data should be visibly qualified so business users do not over-read it.

5. Match metrics to business maturity

The right KPI is the one the business can act on now, not the most impressive-looking dashboard metric.

6. Automate reality, not an idealized API landscape

Where platforms lacked usable host APIs, the workflow made manual input fast, structured and auditable instead of pretending full automation existed.
